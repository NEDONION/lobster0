# Lobster0 Codex 对话沉淀工作流

## 目标

每轮有效开发完成后，把产品范围、架构决策、运行方式和后续任务同步进仓库，避免信息只留在聊天中。

## 沉淀位置

| 内容 | 文件 |
| --- | --- |
| 产品定位、功能范围、验收标准 | `docs/product/20260807_产品需求文档.md` |
| 模块边界、主链路、扩展原则 | `docs/architecture/20260807_系统架构.md` |
| 安装、CLI、配置和故障排查 | `docs/getting-started/20260807_本地运行指南.md` |
| 可执行实施步骤 | `docs/superpowers/plans/` |
| 项目简介和最快入口 | `README.md` |

## 每轮结束检查

- 是否新增或修改了命令、配置、依赖或运行方式。
- 是否改变了 Agent、Channel、Tool、Policy、Storage 或 Evolution 的边界。
- 是否改变了 MVP 范围、非目标、验收标准或里程碑。
- 是否产生必须继续完成的实施任务。
- README 与 docs 是否仍然只陈述已实现行为。

有变化时更新对应文档；没有变化时不为记录而制造新文件。

## 推荐记录格式

需要保留一次重要决策时，在最相关文档中追加：

```markdown
## YYYY-MM-DD 变更记录

- 背景：
- 决策：
- 影响：
- 验证：
- 后续：
```

实现计划放进 `docs/superpowers/plans/`，正式使用方式仍以 README、PRD、架构和本地运行指南为准。
