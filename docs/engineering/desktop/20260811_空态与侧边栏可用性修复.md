# Desktop 空态与侧边栏可用性修复

> 日期：2026-08-11
> 文档类型：D1 跟进修复实现记录
> 状态：`IMPLEMENTED`（2026-08-11）
> 上位设计：[D1 打开即聊设计](../../superpowers/specs/2026-08-10-desktop-d1-conversation-shell-design.md)
> 视觉基准：[Claude 风格视觉迁移](../../superpowers/specs/2026-08-11-desktop-visual-refresh-claude-inspired-design.md)

## 1. 触发来源

用户在真实使用中反馈三点（原话）：

1. "这个新建对话窗口太诡异了"；
2. "为什么 Logo 还是 M 都不需要有 Logo 在这里吧"；
3. "左侧侧边栏的样式能给我整体优化一下吗"。

## 2. 问题 1：空态出现两层重复标题

### 根因

[task-workbench.tsx](../../../desktop/src/renderer/task-workbench.tsx) 无论有没有对话，都会渲染
`conversation-header`（`CONVERSATION` + `新对话` + `等待开始` 状态标签）。空态下它与居中的
`conversation-invite`（`今天想完成什么？`）语义重复，中间还被撑出一大片空白，视觉上像是页面加载了一半。

对照 ClawX 和 Claude 的空态：都是**只有一个居中的大标题 + 输入框**，没有额外顶栏。

### 方案

空态不渲染 `conversation-header`，整块区域交给 `conversation-invite`；`.conversation-panel[data-mode="empty"]`
的 grid 行数从 `auto minmax(0,1fr)` 改为单行 `minmax(0,1fr)`。有对话时行为完全不变（顶栏照常显示当前
状态），因此不影响运行中/审批/失败态的可见性。

顺带把顶栏标题里的三元表达式去掉——它只在 `emptyTask === false` 时渲染，`新对话` 分支已成死代码。

## 3. 问题 2：Logo 仍是重命名前的 "M"

`brand-mark` 是硬编码字符串 `"M"`（MiniClaw 的首字母），重命名为 Lobster0 后未同步。用户明确表示
这个位置不需要 Logo，因此整块移除，侧栏顶部只保留 `Lobster0` 文字，`.brand-mark` 的 CSS 一并删除
（否则是死规则）。`.brand` 改为固定 32px 行高，与下方「新建对话」按钮和导航项的高度节奏对齐。

## 4. 问题 3：侧边栏优化

| 项 | 问题 | 处理 |
| --- | --- | --- |
| 历史会话状态 | 直接渲染 Core 的原始枚举串（`waiting_approval` / `completed` / `failed`），既是英文技术术语，又因为每条都显示而变成噪音 | 新增 `sessionStatusLabel()`：`completed` 映射为 `null` 不渲染（它是绝大多数会话的常态），其余翻译成中文并渲染为小胶囊；`failed` 红、`waiting_approval` 橙、`running`/`queued` 用强调色，与语义色保持一致 |
| 未知状态 | —— | 原样透出而不是静默吞掉，便于发现 Core 新增状态；有测试锁定该行为 |
| 底部 `W1` 徽标 | 内部阶段代号，对用户无意义 | 移除，`.sidebar-status` 从三列 grid 简化为 flex |
| 底部文案 | `Core ready` / `Core offline` 是英文 | 改为「已连接本地 Core」/「未连接本地 Core」 |
| 自动化页说明 | 文案里残留 "W1 仅提供只读信息" | 改为「当前为只读」 |

### 4.1 历史对话按时间分组（第二轮）

用户确认第一轮效果后要求继续，补上 ClawX 那样的时间分组。新增
[session-groups.ts](../../../desktop/src/renderer/session-groups.ts)：

- `sessionGroupKey(updatedAt, now)` 把会话分到 `today` / `yesterday` / `week`（7 天内）/
  `month`（30 天内）/ `earlier` / `unknown` 六档；
- `groupSessionsByRecency()` 保留 Core 已有的 `updated_at DESC` 组内顺序，丢弃空分组；
- `SESSION_GROUP_LABELS` 提供中文标题（今天 / 昨天 / 最近 7 天 / 最近 30 天 / 更早 / 时间未知）。

**关键正确性点：按本地日历日分组，而不是按经过的小时数。** Core 返回的是 UTC ISO 时间戳
（如 `2026-08-10T20:55:22+00:00`），而用户感知的"今天/昨天"是本地日历日。若用毫秒差除以 24h，
东八区凌晨的会话会被误判成"昨天"——因为它距当前不足 24 小时却已跨过本地零点。实现把两个时间点
都归一化到各自本地日的 `00:00` 再算天数差，测试里专门有一条用例锁定这个边界（今天 00:30 与昨天
23:30 相距不到 24 小时，但必须落进不同分组）。

另外两个兜底：无法解析的时间戳归入 `unknown` 而不是抛错或静默丢弃；时钟回拨/Core 时间超前导致的
未来时间戳按 `today` 处理，不会掉进 `earlier`。

渲染上，`.sidebar-recent-group` 之间用 10px 外边距拉开，比组内条目 1px 的间距明显，让分段一眼可辨；
原先固定的"最近对话"单一标题由各分组标题取代。

## 5. 一处自我纠正

截图上邀请区看起来左右不对称、偏左，一度准备调整 `.conversation-invite` 的居中方式。改之前先用
`getBoundingClientRect()` 实测，结果是 `leftGap = rightGap = 193px`，**本来就是精确居中的**——视觉
偏移感来自输入框内左对齐的 placeholder 和右下角发送按钮的重量分布。因此未做任何改动，避免了去"修"
一段正确的代码。

## 6. 验证

- `pnpm test`：48/48 通过（第一轮 40 + 分组的 8 条）。分组按 TDD 做：先写
  `test/session-groups.test.ts` 跑出预期失败（模块不存在），再写最小实现转绿；
- 测试覆盖：空态不再出现 `conversation-header`、`sessionStatusLabel` 的三类行为（隐藏 completed、
  翻译需关注状态、透出未知状态）、分组的六档边界、**跨本地零点但不足 24 小时的时区边界**、
  非法时间戳、未来时间戳、组内顺序保持、空分组丢弃；
- `pnpm typecheck`、`pnpm build`：干净通过；
- 视觉验证：用真实 `App` 组件 + 真实编译 CSS，构造覆盖全部六个时间分组与全部状态标记的会话列表，
  在 Browser 面板 1280×860 截图核对，并用 `getBoundingClientRect()`/DOM 查询实测分组结构，确认
  六组标题、组内顺序、`completed` 不渲染标记、损坏时间戳落入「时间未知」均符合预期。

## 7. 影响范围

`desktop/src/renderer/` 下 `app.tsx`、`task-workbench.tsx`、`styles.css`，新增
`session-groups.ts`；测试为 `desktop/test/app.test.tsx` 与新增的 `desktop/test/session-groups.test.ts`。
不涉及 Bridge 协议、Core、数据库或任何持久化行为；`SessionSummary` 的 `status` 与 `updatedAt` 原始值
不变，只改变展示层。
