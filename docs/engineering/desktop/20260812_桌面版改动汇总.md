# 桌面版本轮改动汇总（2026-08-11 ~ 08-12）

> 文档类型：面向使用者的改动说明
> 范围：Desktop D2b、D2c、D3 三个 milestone，以及随后一次「承诺对照核查」修掉的八处缺口
> 相关设计：[D2b 多 Provider](../../superpowers/specs/2026-08-11-desktop-d2b-model-provider-config-design.md)、[D2c 附件](../../superpowers/specs/2026-08-11-desktop-d2c-attachments-design.md)、[D3 共享产物](../../superpowers/specs/2026-08-11-desktop-d3-artifacts-design.md)

## 1. 一句话

桌面版从「只能聊天」变成了「能换模型、能发附件、能看产物、能查定时任务到底干了什么」。

## 2. 新增能力

### 2.1 设置页可以配置模型（D2b）

- 新增 **Models 区**：列出全部 Provider，可新增 / 编辑 / 删除 / 设为默认 / 填 API Key；
- 支持**多 Provider 并存**（配置文件从单个 `[provider]` 升级为 `[[providers]]` 数组表，旧配置不改一个字也能继续用）；
- 改完可以直接点**「重启 Core」**，不用自己关掉应用重开。

密钥的处理边界：

- `providers.set_secret` 的请求里**只有 `{id, value}`，没有变量名**——变量名由 Core 从 id 推导，界面在结构上就没有指定写哪个环境变量的能力；
- 响应只回「是否已配置」，明文永不回流，异常文本也不透传（可能带上路径或值）；
- 当前默认 Provider 拒绝删除（会留下悬空引用），界面连入口都不给。

### 2.2 发消息可以带附件（D2c + D3）

- Composer 有了 `📎`，可以选一个本地文件随消息发送；
- 文件走 `ArtifactStore` 的完整校验：拒绝 symlink、大小上限、magic byte 嗅探、TOCTOU 复查；
- **模型真的能读到内容**：消息末尾附一段由 Core 生成的附件清单，模型用新增的 `read_artifact` 工具读取正文。

两处值得说明的取舍：

- 清单里的**类型与大小一律从 Store 读**，调用方谎报不了；只有文件名来自调用方，因为它本来就是用户自己的字符串（入库前去掉不可打印字符并截断）。
- 截断必须**显式声明**。静默截断会让模型把半截内容当成文件的全部，比读不到更糟。

### 2.3 右侧产物面板（D3）

- 当前会话有产物时右栏才出现（用户上传的、以及 Agent 截图/下载的）；
- 文本与图片可内嵌预览，其他类型「在访达中显示」；
- **不做**「用系统默认应用打开」——那等于给渲染进程开一个本地执行入口，且 `.zip`/`.pdf` 在不同机器上关联到什么程序不可控。

### 2.4 定时任务能看清到底干了什么

之前一条运行记录只有「时间 + 状态 + 一个英文错误码」。现在：

- 耗时、token 用量、结果摘要；
- 失败原因翻成中文（未知错误码仍原样露出，否则无从排查）；
- **「查看完整过程」**可跳到那次运行的会话，看到每一段思考与每一次工具调用；
- 新建任务默认「**立即执行一次**」，不再要求填时间。

### 2.5 其它

- **权限模式**从四个小写单词变成四张带说明的卡片（SAFE / SMART / AUTOPILOT / YOLO），后两档标「需谨慎」。文案对着 `policy/engine.py` 的真实判定写，不是想当然的描述；
- **`manage_task` 工具**公开了 `schedule` / `delivery` / `budget` 的字段形状。此前它们是裸的 `{"type": "object"}`，模型无从得知字段名，只能一次次猜、一次次被拒；
- **`http_get` 支持声明可信网段**（`tools.http_get.trusted_cidrs`）。fake-IP 模式的代理会把所有域名解析到 `198.18.0.0/15`，SSRF 防护看到非公网 IP 就拒绝，导致 `http_get` 在这类机器上完全不可用。豁免有硬红线：回环、`169.254.169.254` 云元数据、RFC1918 内网永远拒绝，哪怕写了 `0.0.0.0/0`。

## 4. 承诺对照核查：八处「说了但没接上」

三个 milestone 都标记完成后，逐条把设计文档的承诺与真实代码对照了一遍，找出**八处**功能没有真正接通。详见[分 Phase 落地文档 §4.11](20260810_桌面多Agent分Phase落地.md)。

八处**没有一处是逻辑写错**——每个部件单独看都对，测试也都是绿的。问题全部出在**部件之间的接缝**：组件没被传参、字段没人读、写路径只覆盖一半分支、effect 依赖漏了触发时机。

单元测试天然测不到这类问题：它验证的是「组件在被正确调用时行为正确」，而不是「组件真的被调用了」。
