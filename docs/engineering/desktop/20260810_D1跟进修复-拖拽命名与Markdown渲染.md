## 1. 触发来源

用户在真实使用桌面应用后反馈三个问题（原话）：

1. "桌面版很难拖动"；
2. "为什么是创建新任务，而不是创建新对话"；
3. "markdown 排版和样式都不太好，没有特别适配和展示很多元素"（附真实飞书查询结果截图，显示原始
   `**粗体**`、`| 表格 |` 语法未被解析）。

三者都不是 D1 设计文档遗漏的功能，而是 D1 落地时的实现缺口，逐一排查后确认如下。

## 2. 问题 1：窗口无法拖动

### 根因

[src/main/index.ts](../../../desktop/src/main/index.ts) 中 `titleBarStyle: "hiddenInset"` 移除了系统
标题栏，只保留左上角红绿灯。但渲染层 CSS 里没有任何 `-webkit-app-region: drag` 声明，窗口不存在
任何可拖拽表面，只能勉强抓红绿灯周围几像素。

### 方案

在 `.app-shell` 内新增一个 `position: fixed` 的顶部通长拖拽条（`.app-drag-region`，高度 40px），
不改变现有 DOM 层级：

- 侧栏 `.sidebar` 的 `padding-top: 40px` 本来就是为红绿灯预留的，品牌区在拖拽条下方，不冲突；
- 任务视图下 `.workspace-header`（`padding-top: 12px`，高 32px）会与拖拽条重叠，但该区域只有
  `<span>` 文案（`CONVERSATION`/`Core 已连接`），没有可点击元素，重叠不影响交互；
- 自动化/设置视图下 `.workspace-header` 顶部偏移是 40px，不重叠。

跨平台上，Windows/Linux 默认仍有原生标题栏（本次未改 `titleBarStyle` 的平台分支），额外的
`-webkit-app-region: drag` CSS 对原生 frame 无副作用。

### 验证

`scripts/smoke-electron.mjs`（真实 Electron + 真实 Python Bridge）新增断言：
`getComputedStyle(.app-drag-region)['-webkit-app-region'] === 'drag'`，失败即非零退出。

## 3. 问题 2：「新建任务」→「新建对话」

### 决策过程

D1 设计文档刻意使用「任务」这一产品术语（区别于纯聊天，为 D2～D4 的子 Agent/Artifact 铺路）。
但当前体验就是纯对话，术语与体验不一致。此项通过 `AskUserQuestion` 与用户确认，用户选择
"改为对话（推荐）"：**只改用户可见文案，不改内部标识符和架构**。

### 改动范围（仅 UI 文案，不动代码结构）

| 文件 | 旧文案 | 新文案 |
| --- | --- | --- |
| [app.tsx](../../../desktop/src/renderer/app.tsx) | `新建任务` 按钮 | `新建对话` |
| app.tsx | `最近任务` / `还没有历史任务` | `最近对话` / `还没有历史对话` |
| app.tsx | `VIEW_COPY.task.eyebrow = "TASK WORKBENCH"` | `"CONVERSATION"` |
| app.tsx | 错误提示"最近任务读取失败"/"任务历史读取失败" | "最近对话读取失败"/"对话历史读取失败" |
| [task-workbench.tsx](../../../desktop/src/renderer/task-workbench.tsx) | `aria-label="任务工作台"` | `"对话工作台"` |
| task-workbench.tsx | `新任务` / `当前任务` 标题 | `新对话` / `当前对话` |
| task-workbench.tsx | `aria-label="任务内容"`（textarea） | `"消息内容"` |

明确不改的：自动化相关文案（"定时任务"）、`sessionKey`/`TaskWorkbench`/`task-state.ts`
等内部标识符、`task-layout`/`task-status` 等 CSS class 名——这些属于架构命名，不属于本次
"文案对齐体验"的范围，且改动会牵动更大面积的代码和历史文档引用。

### 验证

`test/app.test.tsx` 断言首屏包含"新建对话"/"最近对话"、`aria-label="消息内容"`。

## 4. 问题 3：Markdown 不渲染

### 根因

[task-workbench.tsx](../../../desktop/src/renderer/task-workbench.tsx) 所有消息、思考、工具摘要、
最终回复此前都是 `<p>{content}</p>` 纯文本输出，零 Markdown 解析。真实 Agent 回复（如飞书查询
结果）包含表格、粗体、链接时，用户看到的是原始 Markdown 源码字符。

### 方案

新增 [markdown.tsx](../../../desktop/src/renderer/markdown.tsx)，用 `react-markdown@10` +
`remark-gfm@4` 渲染为真实 React 元素（不使用 `dangerouslySetInnerHTML`，避免 Agent/工具输出中
可能包含的不可信内容造成 XSS）。接入位置：

- 时间线里的 user/assistant 消息、reasoning、tool 摘要、系统提示；
- 结果面板的最终回复（`task.run.lastAssistantText`）。

链接固定 `target="_blank" rel="noopener noreferrer"`；主进程 [index.ts](../../../desktop/src/main/index.ts)
新增 `setWindowOpenHandler` + `will-navigate` 拦截，只有 `http(s):` 协议通过 `shell.openExternal`
在系统浏览器打开，其余一律 deny——否则新渲染出的链接点击后 Electron 默认行为是静默拦截，等于
死链接。

CSS（[styles.css](../../../desktop/src/renderer/styles.css)）新增 `.markdown` 一整套样式：标题、
粗体/斜体、有序/无序列表（含 `list-style`，因为 Tailwind preflight 默认清空了它）、行内代码、
代码块、引用、分隔线、表格（含横向滚动容器 `.markdown-table-wrap`，避免宽表格撑爆消息气泡）。
消息气泡的圆角/背景从原来挂在 `<p>` 上改为挂在 `.markdown` 容器整体上，因为一条消息现在可能
包含多个 Markdown 块（不再是"一个 `<p>` = 一条消息"）。

结果面板原先用 `-webkit-line-clamp` 截断纯文本 `<p>`，对混合内容（表格+文字）不可靠，改为
`max-height: 320px; overflow-y: auto`。

### 验证

- `test/markdown.test.tsx`：`renderToStaticMarkup` 断言 `**粗体**`/`| 表格 |` 源码字符不出现在
  输出里，`<strong>`/`<table>`/`<td>`/`href`/`target="_blank"` 确实出现；
- 用真实编译后的 CSS（`electron-vite dev` 服务的 `styles.css`）+ 真实 `Markdown` 组件，塞入与
  用户截图同构的示例内容（表格 + 粗体 + 链接 + 代码块 + 嵌套列表），在 Browser 面板截图核对，
  修了一处遗漏（`ul`/`ol` 没有项目符号，同样是 Tailwind preflight 导致）后视觉确认通过。

## 7. 已知问题 / 遗留风险

1. **pnpm store 双版本冲突**：本机同时存在系统 `pnpm@7.29.2` 和项目锁定的
   `corepack pnpm@10.14.0`，两者 store 目录不同，混用会报 `ERR_PNPM_UNEXPECTED_STORE`。
   本次统一用 `corepack pnpm --store-dir /Users/nedonion/.local/share/pnpm/store/v10`，
   后续所有 `desktop/` 依赖操作都应走 `corepack pnpm`，不要直接用裸 `pnpm`。
2. **`pkill -f "electron@43.2.0"` 误伤范围过大**：本次调试为清理自己遗留的 smoke/dev Electron
   进程，用了按可执行文件路径匹配的 `pkill`，该路径下所有 Electron 进程（包括同仓库其他并发
   会话开的 `pnpm dev`）都会被一并杀掉。已确认造成了一次误杀（另一个会话的 dev server 端口
   5173 被释放）。后续清理应优先用 `pgrep`/`ps` 先核对 PID 再精确 `kill`，不要用可执行路径做
   宽泛 `pkill`。
3. **并发编辑**：调试过程中发现 `.gitignore`、`src/lobster0/storage/conversations.py` 被非本次
   任务的改动修改（应为仓库内另一并发会话所为），本次任务未触碰、未回滚这两个文件，原样保留
   给对应会话处理。
