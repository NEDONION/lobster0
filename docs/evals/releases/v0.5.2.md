## 1. 版本能力

| 能力 | 版本结果 |
| --- | --- |
| 飞书正常回答 | completed card 是唯一回复，不再追加重复文本 |
| 飞书卡片样式 | Markdown 正文使用 `small`（12px） |
| 超长回答 | 卡片保留前缀，只把未展示后缀回复到该卡片 |
| 卡片失败 | 创建 durable text fallback |
| Restart recovery | 稳定 progress UUID 恢复同一卡片，不补发普通全文 |
| Waiting approval | tool-call content 只在内存缓冲；只发布 durable Approval card |
| Telegram / Discord | 继续 preview + durable final text |
| 飞书业务 API | Skill → `run_command` → official `lark-cli` |
| Provider Tool 分片 | 忽略合法 Tool 名之后的 empty-name continuation |
| Gateway | SDK 在主 asyncio loop 前加载；优先 `connect_until_ready()` |

### 2026-08-09 后续实现补充

- 飞书 completed card 已升级为结构化 `Claw Trail`：展示脱敏步骤、Tool、安全目标、状态、耗时、过程摘要和最终答案；
- `model_reasoning`、原始 Tool 参数与输出不进入卡片或持久 trace；
