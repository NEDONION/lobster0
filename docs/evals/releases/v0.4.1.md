## 本版本新增的固定事故场景

| ID | 防止回归的行为 |
| --- | --- |
| `FILES-PERSONAL-READ-001` | Personal Profile 能读取合成 Home 普通文件 |
| `FILES-PERSONAL-WRITE-APPROVAL-001` | Personal 外部写根必须停在参数绑定 Approval |
| `CLI-DISCOVERY-LARK-001` | NVM wrapper 与 `env node` 使用同一确定性 PATH 启动 |
| `CLI-SENSITIVE-DENY-001` | 模型不能用命令绕过敏感文件硬拒绝 |

离线场景全部使用临时 Home、临时多根与 fake executable，不扫描个人电脑。唯一真实本机 smoke 只执行
`lark-cli --version`，不联网、不读取认证状态、不修改文件，也不把 Home 或完整 PATH写入记录。

## 为什么还不能写“飞书 CLI 已经可用”

这次已经证明 Lobster0 能发现并启动本机 NVM 下的 `lark-cli`。但“程序能启动”与“账号已登录、应用 Scope
足够、企业策略允许”是三层不同事实。发布前仍要由 Owner 显式批准并运行认证/只读 OpenAPI smoke；在此之前
不能把真实飞书能力标成 production verified。

完整配置、权限矩阵与排障方法见
[Personal Machine 权限与本机 CLI 发现](../../engineering/phase-2/20260808_personal-machine-permissions.md)。
