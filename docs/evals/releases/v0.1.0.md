## 本版本关闭的真实事故

用户 query `帮我看看我的电脑是什么配置` 曾返回：

```text
error: model provider tool arguments is invalid
```

原因是 DeepSeek-compatible SSE 可以先发送 `function.arguments: ""`，而旧 parser 在聚合前把空字符串当作
非法必填值。`PROTO-001` 先用精确 SSE 输入复现 RED，再在共享聚合点允许空字符串片段；非字符串片段和最终
非 JSON object 仍被拒绝。

## 复现命令

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/ruff check --no-cache .
.venv/bin/miniclaw eval validate --root evals/scenarios
.venv/bin/miniclaw eval run --suite offline --root evals/scenarios
```

预期最后一行：

```text
Offline eval: 10/10 passed, 0 failed (...ms).
```

## 尚未被这个 PASS 证明的内容

- 没有调用真实 DeepSeek，因此不证明当前账号、网络和模型采样稳定；
- 没有飞书、Telegram 或 Discord Channel，因此不证明 IM 交付；
- 没有 write、Shell、HTTP、长期 Memory、Skills 或自动提案；
- `system_info` 会真实执行只读收集，但 gate 不把本机详情写进 baseline；
- 794 ms 只用于定位明显退化，不是跨机器 benchmark 指标。

R3 会增加 live DeepSeek release suite、三次采样规则和脱敏报告；R4 再接飞书端到端与外部 benchmark。
