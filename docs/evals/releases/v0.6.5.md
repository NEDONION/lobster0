Browser Worker 的真实 Chromium 用例在 macOS 受限子进程沙箱中可能得到 `SIGABRT/EPERM`。本记录的 14/14 结果来自
允许启动隔离 headless Chrome 的宿主环境；没有把 8 条无浏览器用例冒充完整 PASS。

## 4. 安全验收

- 默认不打开个人浏览器 Profile；Profile、Artifact、staging 均 owner-only 且位于 Workspace 外；
- URL 只允许公网 HTTPS，redirect 每跳重验；localhost、私网和 metadata 地址拒绝；
- password/OTP 永久拒绝，普通输入正文不进入 TUI、Approval、Audit 或 ToolResult；
- click 与 Enter/Space 使用动态高风险并绑定 exact arguments；
- page content 始终标记 `untrusted_web_content`，不能改变 System/Policy；
- snapshot 有界，旧 generation/ref fail closed；
- Screenshot/Download 经 regular-file、MIME/magic、大小、hash 和 TTL 验证；
- cancel、timeout、Worker crash 和 Runtime close 回收进程组，不自动重放网页副作用。

## 5. 已知限制

- Browser 默认关闭，需要先构建 Worker 并在私有配置中显式开启；
- 当前只实现本地 Chromium backend，不提供远程/云浏览器；
- 不自动登录，不读取个人 Cookie，不输入密码、验证码或 OTP；
- 点击统一按高风险处理，尚未细分纯导航按钮与业务提交按钮；
- Artifact 只提供私有 ID/metadata，当前没有独立浏览/导出 UI；
- 页面/Tab 状态不跨 Runtime 重启恢复，未知网页副作用不会自动重放；
- controlled public live smoke 尚未执行。
