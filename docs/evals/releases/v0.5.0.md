## 本版本实现了什么

- `TelegramAdapter`：numeric Owner、DM/group/topic、mention/reply、UTF-16 entity、严格白名单；
- `TelegramTransport`：official python-telegram-bot long polling、get_me、message-only updates、safe send/edit/typing、
  rate limit 与 code-fence-aware 分片；
- `DiscordAdapter`：DM/Guild/Thread、user/guild/channel allowlist、mention/reply、bot/webhook/system filter；
- `DiscordTransport`：official discord.py Gateway、精确 Intents、READY/resume/close、AllowedMentions.none、safe
  send/edit/typing 与错误映射；
- `GatewaySupervisor`：一个 AgentRuntime、每平台独立 Transport/Delivery/Manager/Experience、静态 all-or-none、运行期
  degraded 隔离、反向清理；
- neutral Approval v2 envelope 与 Feishu v1 read compatibility；
- 20 项 offline Doctor、20 个新 versioned Channel cases、redacted JSON soak report；
- 两个默认拒绝、不主动发送、15 项人工驱动的 live harness。

真实 409/429/403、公网断线重连或长期服务稳定性。

## 为什么不是 production verified

真实验收要求每个平台各自通过 auth ready、20 轮 DM、group/guild addressing、reply/thread、Memory restart、read
Tool、approve/deny、non-owner、dedupe、长文本、rate limit、Gateway restart、断网重连、experience fallback 和 Secret
scan 共 15 项。

本轮未运行带 `--confirm-live` 的 Telegram/Discord harness，也没有提交 `.local/eval-results/` 中的本地 evidence。
因此不能把 fake SDK、32/32 或 640/640 写成 live PASS。

真实执行入口：

```bash
uv run python scripts/telegram_live_smoke.py --confirm-live
uv run python scripts/discord_live_smoke.py --confirm-live
```

任一 skip/fail 返回非零。evidence 不得包含 Token、完整平台 ID、username、群名、正文或截图。
