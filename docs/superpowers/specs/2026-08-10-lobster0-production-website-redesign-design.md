# MiniClaw Production-grade 官网视觉重设计

## 1. 目标与边界

本轮只重做 `website/` 的视觉表达与首页交互，不更换已经确定的 Next.js 16 + Fumadocs
架构，也不新增营销路由。官网继续由同一仓库维护，Vercel Project Root Directory 保持为
`website/`。

质量目标是达到成熟开源 Agent 项目的产品官网水准：信息紧凑、品牌清楚、交互有节奏，且所有
能力和数字均能从当前仓库验证。可以借鉴 LobsterAI、OpenAgents、OpenClaw、Hermes 等站点的
构图与动效方法，但不复制其代码、资产、Logo 或具有识别性的页面装饰。

首页仍只保留约三屏：

1. 品牌 Hero 与工程证据。
2. 能力 Tabs 与可检查的执行链。
3. 真实 Workbench、快速开始与贡献入口。

文档继续使用 Fumadocs，路由和中英文内容结构不变。

## 2. 已确认的视觉方向

整体采用已确认的“机械爪版”产品化构图：浅色画布、居中 Hero、悬浮入口卡、精细面板、明确的
运行轨迹和丰富但有秩序的状态色。机械爪只作为构图参考，不再作为品牌 Logo。

品牌 Logo 恢复为最初的三枚向右箭头标记：深色圆角底，蓝、绿色与浅色箭头依次推进。页头、
Hero、favicon、Open Graph 与文档导航统一使用同一套箭头几何，不再出现字母 `M` 占位标记或
机械爪 Logo。

Hero 主标题控制在桌面端最大 `54px`，Section 标题最大 `36px`；移动端按视口缩放。标题不再
依靠超大字号占据页面，信息层级由字重、行高、对齐和面板密度建立。

## 3. 颜色与字体

视觉 token 限定为六个基础角色：

- Canvas `#F4F7FB`：页面底色。
- Paper `#FFFFFF`：卡片、面板与导航。
- Ink `#121722`：文字、深色按钮与 Logo 底。
- Signal Blue `#4267F5`：主操作、活动轨迹与 TUI 入口。
- Coral `#F16C56`：飞书、风险和需要注意的事件。
- Green `#2CAF88`：Telegram、完成与健康状态。

Amber 与 Violet 仅作为由组件语义派生的局部状态色，不扩展为新的大面积主题色。页面不使用
通用 AI 渐变光球；色彩主要出现在轨迹节点、入口标记、指标顶线、活动 Tab 和状态反馈。

沿用现有字体，不增加依赖：Instrument Sans 负责英文与数字，系统中文无衬线字体负责中文，
IBM Plex Mono 负责命令、事件名和工程指标。

## 4. 三屏信息架构

### 4.1 Hero 与证据

首屏采用居中产品式构图。箭头 Logo 位于主标题上方，左右分布 TUI、飞书、Telegram、Discord
四个入口卡，细线轨迹在入口与 Core 之间流动。主要内容包括：

- 中文定位语与不超过两行的说明。
- “五分钟开始”和“查看源码”两个 CTA。
- 一个 Python Core、四个入口、18 个内置工具、33 个入口场景验证、15 个自动化场景验证。
- Implementation PASS 与 Live PASS 的准确边界，不用营销措辞掩盖验证状态。

首屏不放大段终端，不伪装成在线控制台。

### 4.2 能力 Tabs

第二屏使用单个稳定尺寸的交互面板，通过 Runtime、Channels、Safety、Memory、Automation 五个
Tabs 原地切换。每个 Tab 固定包含一句结论、一张结构图或状态面板、三至五条仓库事实。

中文页面的标题、标签、状态与解释均使用中文。`AgentRuntime`、`Policy`、`Tool`、事件名和命令
等必要专有名词可以保留英文，但必须紧邻中文解释，不出现整块英文界面。

### 4.3 Workbench 与 Quick Start

第三屏继续使用真实 TUI 证据，通过审批、外部 CLI、多入口三个 Tabs 展示执行过程。图片只使用
仓库中已有的真实截图；动画用于解释步骤，不生成不存在的后台界面。Quick Start、Docs、GitHub
和贡献入口直接收束在同一屏底部，不再增加第四个营销 Section。

## 5. 动画系统

页面需要持续可感知的动态，但所有动画共享同一节奏，避免每个组件各自抖动：

- 首次进入：导航、Logo、标题、CTA、指标依次出现，总时长不超过 `900ms`。
- Logo：三枚箭头按顺序描边或点亮，只在首次进入和 hover 时播放。
- Runtime 轨迹：节点信号沿曲线运行，周期约 `3.6–4.8s`，只使用 transform 与 opacity。
- 入口卡：极小幅度、不同相位的悬浮，避免整齐同步。
- 指标条：数字进入视口时完成一次计数或翻牌，不无限循环。
- Tabs：指示器滑动，内容以 `180–320ms` 的短距离位移与裁剪切换，面板高度保持稳定。
- Workbench：日志、审批高亮与结果按真实顺序出现，完成后停在最终态。
- Hover：按钮、卡片和链接只做 `1–3px` 位移、边框或阴影变化。

`prefers-reduced-motion: reduce` 下取消持续轨迹、悬浮和计数，直接展示最终状态。动画不能阻塞
内容、键盘操作或页面滚动。

## 6. 精度、响应式与可访问性

- 桌面端内容宽度控制在约 `1280px`，使用统一 12 列网格和 8px 间距基准。
- 面板使用细边框、轻阴影和小圆角；避免松散 Bento 堆叠与夸张玻璃效果。
- 390px 移动端不得横向溢出；入口卡折叠为紧凑轨道，Tabs 可横向滚动。
- 交互目标不小于 44px，焦点环清晰，颜色不是唯一状态信号。
- Tabs 使用标准 ARIA 语义并支持方向键、Home 与 End。
- 关键内容在 JavaScript 或动画失败时仍存在于服务端 HTML。

## 7. 内容与真实性

中文首页默认只展示中文用户文案。允许保留的英文限定为产品名、协议名、代码、命令、事件标识和
GitHub 等专有名词；其余导航、按钮、Tabs、状态、图片说明和辅助文本均翻译为中文。

网站继续从共享项目事实文件读取版本、入口、工具、评测数和安装命令，组件不得复制这些数字。
不添加在线 Demo、云端后台、实时监控、虚构客户评价或尚未实现的功能。

## 8. 实现与发布验收

实现阶段优先复用现有组件、Motion 依赖、内容契约和真实图片，只重构必要的营销组件与 CSS，不
引入新的 UI 框架或动画依赖。

完成前必须通过：

- TypeScript、ESLint、组件测试和 Next.js production build。
- Playwright 桌面与 390px 移动端验收，覆盖中英文、五个能力 Tabs、三个 Workbench Tabs、
  reduced-motion、内部链接和控制台错误。
- 浏览器截图对比，确认 Logo、标题尺度、中文覆盖率、动画层级和三屏长度。
- `git diff --check` 与仓库文档校验。

Vercel Project 已连接 GitHub 仓库，Root Directory 为 `website/`。发布顺序固定为：从已验证提交
创建新 Preview，浏览器复验通过后再覆盖 Production；不提升此前未被用户接受的旧 Preview。

## 9. 非目标

本轮不增加博客、定价、登录、CMS、多版本文档、实时 GitHub Star、WebGL、3D 模型或新的站点
依赖。Logo 不再探索其他方向；已确认使用最初的三箭头版本。
