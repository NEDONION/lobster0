# 附件回到消息里：气泡内展示与跨轮次可见

> 日期：2026-08-12
> 文档类型：功能设计（**写于实现之前**）
> 状态：`IMPLEMENTED`（2026-08-14，见 §8）
> 相关：[D2c 附件](2026-08-11-desktop-d2c-attachments-design.md)、[D3 共享产物](2026-08-11-desktop-d3-artifacts-design.md)
> 并行工作：[多模态输入统一设计](../../engineering/phase-8/20260814_多模态输入统一设计.md)
> 覆盖的是**入站管线**（渠道 → 模型）；本文覆盖**展示与携带范围**，两者不重叠。

## 1. 起因

Owner 上传一张图后提出两点：

> 我上传的图片在桌面版里面为什么完全看不见？……直接做成 Message 放在对话框里，而不是放在右侧面板
>
> 桌面版是不是还不能发多模态信息，并且对话模型和看图的模型不互通上下文

## 2. 现状核查（三条里有两条与直觉相反）

| 说法 | 核查结果 |
| --- | --- |
| 图片在对话里看不见 | **属实**，且根因在 Core |
| 不能发多模态 | **不成立**。`turn.py` 会把图片作为 `image_url` 拼进请求，`media/attachments.py` 已实现 |
| 对话模型与看图模型不互通上下文 | **不成立，但直觉指向了一个真问题**（见 §2.3） |

### 2.1 图片看不见的根因：历史消息不带附件

Core 在 `create_with_user_message` 时把附件摘要写进了该条用户消息的
`metadata_json`，但 `session.history` **从没把它下发**——`SessionMessage` 只有
`role` / `content` / `turn_id` / `reasoning` / `tool_calls` / `tool_name`。

于是渲染层即使想在气泡里显示附件，也不知道这条消息带了什么。这是本项目第十处
「数据在库里、没人往外发」。

### 2.2 多模态已经可用

`turn.py` 里图片字节**只在发请求那一刻读**：上传时不读、纯文字轮次也不读；读失败
不让整轮挂掉，附件仍以文字清单留在上下文里，模型可用 `read_artifact` 兜底。

这也推翻了 D3 文档里「D3 不做 Vision」那句结论——实现已经走在前面。

### 2.3 真正的问题：图片只在上传那一轮存在

模型切换（`media/switching.py`：带图切视觉后端）**不丢上下文**——同一个请求对象、
含完整历史，只是换了后端。

但 `summaries` 只来自**当前这一轮**的附件：

- 上传那一轮：图片进请求，模型看得见；
- **下一轮追问「这图里第三行写的什么」**：`summaries` 为空，图片不再进请求，模型只
  看到历史里那行文字清单。

Owner 感觉到的「不互通」是这个，不是模型切换。

## 3. 本次要做什么

### 3.1 Core：历史消息下发附件

`session.history` 的每条消息补上 `attachments`（从 `metadata_json` 读），字段与
`attachment.stage` 的响应一致：`artifact_id` / `filename` / `media_type` / `size_bytes`。

**不下发图片字节**：历史可能有几十条消息，每条都塞 data URI 会让一次 `session.load`
变成几十兆。缩略图按需通过已有的 `artifacts.preview` 取。

### 3.2 Desktop：附件回到消息气泡

用户消息气泡下方显示附件：

- **图片**：显示缩略图（点击放大），通过 `artifacts.preview` 取 data URI；
- **非图片**：文件名 + 大小的 chip，与 Composer 里的样式一致。

右栏**保留**——它的职责不同：右栏是「这个会话产生过什么」的汇总（含 Agent 产生的
截图/下载），气泡里是「这条消息带了什么」。两者不重复，删掉右栏会让 Agent 产物
无处可去。

### 3.3 跨轮次可见：把最近的图片带回上下文

新增配置 `[attachments] carry_over_turns`（默认 `1`）：**最近 N 轮内上传的图片，在后续
轮次继续进入模型请求**。

为什么默认是 1 而不是"永远带着"：

- 图片是上下文里最贵的部分，一张 400KB 的图每轮重复发送会迅速烧掉预算；
- 默认 1 表示「上传后紧接着的那一次追问能看到图」，覆盖绝大多数「这图里 X 是什么」
  的场景；
- 想让它一直可见的人可以调大，但那是**显式选择**，不是默认代价。

**上限**：无论配置多少，一次请求最多带 `attachments.max_images_per_request`（默认 4）
张图——防止一轮里翻出十几张历史图片把请求撑爆。

## 4. 不可放宽的边界

- 图片字节**不进历史响应**，只在模型请求里出现，且只在需要那一刻读；
- 缩略图走 `artifacts.preview`，沿用 D3 的归属判定（只能预览已关联到当前会话的产物）；
- 渲染层拿不到文件系统路径（D3 的边界不变）。

## 5. TDD 起点

Core：

- `session.history` 下发 `attachments`，且**不含图片字节**；
- 没有附件的消息不出现该字段（旧客户端不受影响）；
- `carry_over_turns = 0` 时行为与今天完全一致（回归防线）；
- `carry_over_turns = 1` 时，上一轮上传的图片出现在本轮请求里；
- 带回的图片数不超过 `max_images_per_request`；
- 携带的是**当前会话**的附件，不会跨会话串；
- 同一张图不会因为"当前轮 + 历史里也有"而挂两次（实施中补，见 §8.2）。

Desktop：

- 用户气泡显示附件 chip；图片显示缩略图；
- 预览失败只影响那一条，不影响消息正文；
- 历史里没有附件字段时不渲染任何东西（兼容旧 Core）；
- 形状不对的单条附件被丢弃，但**整个会话仍能打开**（实施中补：`metadata_json`
  是历史数据，早期写入的形状不一定与今天一致；这一路已经因为 `stringValue`
  拒绝空串让整个会话打不开过一次）。

## 6. 退出条件

1. 上传图片后，**在对话气泡里直接看到它**，不需要去右栏点预览；
2. 上传后紧接着追问图片内容，模型能答上来（默认配置下）；
3. 纯文字会话的请求体与本次改动前逐字节一致；
4. 一次请求带的图片数有上限，且有测试证明；
5. Python + Desktop 全量门禁通过。

## 8. 实施记录（2026-08-14）

### 8.1 §2.3 的判断在 #58 之后仍然成立

写本文时并发会话正在修「上下文压缩把这一轮的图片丢了」（#58：挂图必须在压缩
**之后**，否则重建 request 时图被无声丢弃）。那是**另一个** bug。实施前重新核对
过：`summaries` 依然只来自当前轮，所以「下一轮追问看不到图」这条没有被 #58 覆盖。

### 8.2 三处设计时没想到、实施中才浮现的判断

**（a）当前轮会把带回预算吃光。** `_recent_image_attachments` 倒着走历史时，遇到的
第一条用户消息**就是当前轮**——它此刻已经写进历史。按原设计直接计数，
`carry_over_turns = 1` 会被当前轮吃掉，上一轮一张图都带不回来。改为从 `-1` 起算，
让当前轮不占预算。这条是被测试逼出来的：其余四条用例全绿，只有真正的携带用例失败。

**（b）来源必须是 `list_context` 而不是全量历史。** 压缩之后被移出上下文的轮次，
其图片也不该再回来——否则上下文越压越大，压缩就白做了。

**（c）字段名在存储与线上不一致。** 存储里是 `byte_size`，而 `attachment.stage`
早已把线上字段定为 `size_bytes`。投影时对齐线上约定，免得 Desktop 为同一个概念
维护两个字段名。

### 8.3 附件为什么没有挂在 `UserItem` 上

`UserItem` 定义在共享库 `@lobster0/pi-tui` 里，终端 TUI 也在用。终端渲染不了缩略图，
为它加一个永远用不上的字段还要重建 dist，代价不划算。改为在 `DesktopTaskState` 上
挂一张按条目 id 索引的表——只在追加条目时写入、此后不再变动，不存在与时间线
不同步的窗口。

### 8.4 接线有独立测试

`create_runtime` 是否真的把配置传进 `TurnService` 有单独一条断言。这一路已经出现过
九次「协议/实现写好了但没人接上」，带回图片这条尤其难从界面察觉：不生效时模型
只是"看不到图"，与配置没写时表现一模一样。

### 8.5 缩略图容器始终渲染

原设计只写了"显示缩略图"。实施时改为**容器始终渲染、尺寸由 CSS 固定**：图片是异步
取回的，等它到了再撑开会让整条消息跳一下；取不到就保持空占位，而不是让整条消息
看起来坏掉。

## 7. 明确不做

- 删掉右栏产物面板（职责不同，见 §3.2）；
- 在历史响应里内联图片字节；
- 让模型自动"回看"任意历史图片——那需要检索与相关性判断，是独立的大问题；
- 视频、音频。
