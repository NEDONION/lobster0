# Desktop D4：子 Agent 在界面上的可见性

> 日期：2026-08-12
> 文档类型：D4 界面设计（**写于实现之前**）
> 状态：`DRAFT FOR REVIEW / IMPLEMENTATION PENDING`
> 前置实现：[Phase 9 depth-1 子 Agent](2026-08-12-phase9-depth1-subagent-design.md)（`USABLE`）
> 上位规划：[分 Phase 落地文档 §7](../../engineering/desktop/20260810_桌面多Agent分Phase落地.md)

## 1. 目标

Phase 9 让主 Agent 能把子目标交给受限的子 Agent，但**桌面端目前只做到一半**：运行
列表已经按父子分组，而「这台机器上有哪些子 Agent、各自能干什么」在界面上无处可见。

本次要解决的是一个具体问题：**Owner 看不到自己配了什么，也无从判断某次派发为什么
可用或不可用。**

## 2. 现状核查

开工前对着代码核对（不凭印象）：

| 能力 | 现状 |
| --- | --- |
| `subagents.list` Bridge 请求 | 已实现，返回 id / description / max_turns / timeout_seconds |
| `subagents_read` capability | 已下发 |
| 运行摘要的 `parent_run_id` / `subagent_id` | 已下发 |
| 桌面端运行列表父子分组 | 已实现（`groupRunsByParent`） |
| **Desktop 侧调用 `subagents.list`** | **没有**——协议做好了但没人调 |
| 设置页展示子 Agent | 没有 |

最后两行正是本项目已经出现九次的那类缺口：协议齐了、界面没接。这次在设计阶段就把
它列成必须验证的退出条件。

## 3. 放在哪里

**设置页新增「子 Agent」区**，紧挨已有的 Models 区。

理由：它和 Models 是同一类东西——**关于「这台机器被配置成什么样」的只读事实**，而不是
对话中的操作。放进侧栏会让导航为一个多数用户用不到的功能变长；放进 Composer 则会
误导成「这里可以选用哪个 Agent 回答」，而事实是**派发由主 Agent 自己决定，用户不参与**。

## 4. 显示什么

每个子 Agent 一行：

- **id** 与**描述**（描述是 Owner 自己写的，直接展示）；
- **预算**：最多几轮、几次工具调用、多少秒超时；
- 一句固定说明：**由主 Agent 在后台任务中自行调用，不能再派发**。

**不显示工具集**。这与 `subagents.list` 不下发工具集是同一个决定：工具集是安全边界的
一部分，把它铺在界面上只会多一处需要与配置保持一致的地方，而 Owner 要改它必须去改
配置文件——界面既不能改，展示它就只是噪音。

## 5. 未声明时显示什么

不隐藏整个区，而是显示一句：**尚未声明子 Agent，主 Agent 不会派发子任务。**

理由：空白区域无法区分「没配」与「功能坏了」。这一路已经因为「界面什么都不显示」
浪费过多次排查（右栏产物、运行详情），空态必须自己说明自己。

同时给出**如何启用**的两步提示（写 `[[subagents]]`、把 `delegate_task` 加进
`tools.enabled`）——只有两步同时做到才生效，漏一步会得到一个静默不工作的配置。

## 6. capability 缺失时

Core 未开放 `subagents_read` 时整区不渲染，与 D2a/D2b/D3 一致：旧版 Core 不该看到
一个空区并怀疑自己配错了。

## 7. 明确不做

- **在界面上增删改子 Agent**。它涉及工具集与预算的收窄校验，那些校验现在集中在配置
  加载期（越界即拒绝加载）。搬到界面意味着把同一套规则实现第二遍，两份规则早晚不一致。
  要改就改配置文件，然后用已有的「重启 Core」按钮生效；
- 手动触发一次派发。派发是主 Agent 的决策，给用户一个「立即派发」按钮会造出一条
  Phase 9 里根本不存在的执行路径；
- 子任务的实时进度。子 Run 与父 Run 同表，进度已经体现在运行列表的分组里。

## 8. TDD 起点

Desktop：

- 未声明时显示空态文案与两步启用提示，**而不是空白**；
- capability 缺失时整区不渲染；
- 预算三项（轮数 / 工具调用 / 超时）都出现在卡片上；
- **不出现工具集**（防止后续「顺手加上」）；
- `subagents.list` 失败时只影响本区，不影响 Models 区与其余设置（沿用 D1 §9 局部失败模式）。

## 9. 退出条件

1. 声明了子 Agent 时，设置页能看到它们与各自预算；
2. 未声明时看到的是明确文案与启用方法，不是空白；
3. **Desktop 真的调用了 `subagents.list`**——不是只写了 API 而没人调（这一路的第九处
   缺口就是这样）。验证方式：`grep listSubagents desktop/src/renderer` 必须有命中；
4. Desktop 全量测试、typecheck、build 通过。
