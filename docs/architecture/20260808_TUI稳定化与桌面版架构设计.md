# MiniClaw TUI 稳定化与桌面版架构设计

> 状态：终端方案已落地；桌面版仍是后续路线
> 日期：2026-08-08
> 当前决策：**Python Core + TypeScript @earendil-works/pi-tui**
> 迁移策略：pi-tui 是默认界面；Textual 暂作显式/自动回退；稳定一个版本后再评估删除

## 1. 决策变更记录

本文最初建议“修好 Textual，未来再做 Electron”。这个判断解决了当时已知的 Widget 重建和强制滚底问题，
但没有覆盖后来确认的完整目标：像 Codex 一样的高密度执行流、终端原生选择、跨屏复制、超长粘贴、多行编辑、
审批 Overlay，以及 Python Core 与多个 UI 解耦。

最终采用的方案是：

| 层 | 当前选型 | 职责 |
|---|---|---|
| Agent Core | Python 3.12 | Provider、Context、Memory、Agent Loop、Tool、Policy、Approval、SQLite、Audit |
| 跨语言边界 | stdio NDJSON protocol v1 | 版本握手、Turn、取消、审批、RunEvent、稳定错误 |
| 默认终端 UI | TypeScript + pi-tui 0.84.1 | Alt Screen、ScrollView、Editor、Markdown、Overlay、鼠标选择、OSC52 |
| 迁移回退 | Textual 8 | Node/构建入口不可用时保持产品可用 |
| 未来桌面 UI | 待单独立项 | 复用同一 Core 协议，不复制 Agent Loop |

这不是把 MiniClaw 重写成 TypeScript。TypeScript 只是一层终端显示和输入设备适配；所有真正会改变电脑状态的
动作仍由 Python Core 决策和审计。

## 2. 为什么当前问题不是“把字体调小”

终端应用不能给局部组件设置 70% 字号。字体大小由 Terminal、iTerm、IDE Terminal 或用户配置决定。应用能控制的是：

- 每个信息块占几行；
- 是否使用厚边框、大卡片和过多留白；
- 长内容能否折叠；
- 状态是否压缩到单行；
- 流式更新是否保持组件和滚动位置稳定。

所以“整体缩小 30%”在实现中被转成了可验证的密度目标：Header 一行、Telemetry 一行、角色使用细左标记、
Reasoning 弱色默认展开、Tool 摘要常驻而详情可展开、输入框只在内容需要时增长。

## 3. 已确认的旧 TUI 根因

Textual 版本的两个直接问题是：

1. 每次模型 delta 更新 Markdown，会重建内部节点，终端正在引用的选区随节点消失；
2. 每个 RunEvent 都滚到底部，用户向上阅读或拖选时视口被后台输出抢走。

迁移前已先修复这两点：Assistant 顶层 Widget 保持稳定，流式阶段使用稳定文本容器；只有用户原本在底部时才
继续跟随。该修复继续存在于 fallback，避免 Node 缺失时回到不可用版本。

ProviderProtocolError 还有两个独立根因：

- 历史软上限可能从 Approval child Turn 的孤立 Tool Result 开始，产生非法 Provider 消息序列；
- 部分 OpenAI-compatible 网关把 function.arguments 返回成 JSON object，而不是规范要求的 JSON 字符串。

当前实现分别通过“回退到最近 User 边界”和“严格归一化 string/object 后再验证 JSON object”解决，不通过吞异常
或清空数据库掩盖问题。

## 4. 当前总体架构

~~~mermaid
flowchart LR
    OWNER["Owner"] --> CLI["唯一入口：miniclaw"]
    CLI -->|"Node >= 22.19 且已构建"| TUI["TypeScript pi-tui"]
    CLI -->|"显式或自动回退"| TXT["Textual fallback"]
    TUI -->|"argv 启动；stdin/stdout NDJSON"| BRIDGE["Python Bridge"]
    BRIDGE --> RUNTIME["AgentRuntime"]
    RUNTIME --> TURN["TurnService"]
    TURN --> AGENT["AgentRunner"]
    AGENT --> EXEC["ToolExecutor"]
    EXEC --> POLICY["Policy + Approval"]
    TURN --> DB["SQLite"]
    EXEC --> AUDIT["Audit"]
    BRIDGE -->|"event.*"| TUI
~~~

真实进程树：

~~~text
uv run miniclaw
└─ Python launcher
   └─ node tui/dist/main.js
      └─ python -m miniclaw.bridge --home <state-home>
~~~

为什么让 Node 再启动 Python Bridge：

- Node UI 可以直接监督 Core 是否退出；
- UI 退出时能回收 Bridge；
- stdout 可完全保留为协议通道；
- 不监听端口，不引入 CORS、CSRF、本地 Token 或端口冲突；
- shell:false，不会把用户文本拼进 Shell。

## 5. 信任边界

~~~mermaid
flowchart TB
    subgraph Untrusted["非权威展示层"]
        UI["pi-tui"]
        INPUT["键盘 / 粘贴 / 鼠标"]
    end
    subgraph Trusted["Python Core 权威层"]
        B["Bridge 验证"]
        A["Agent Loop"]
        P["Policy"]
        E["Executor"]
        D["SQLite / Audit"]
    end
    INPUT --> UI --> B --> A --> P --> E
    A --> D
    E --> D
~~~

不变量：

- TUI 不读取 .env、Provider Key 或 SQLite；
- TUI 不能直接运行 Shell、文件 Tool、HTTP 或 lark-cli；
- Allow this session 和 Always allow 只是决定值，最终可用模式和规则范围由 Core 返回并校验；
- Bridge 错误不得携带 Provider body、Key、Prompt、Traceback 或任意原始异常；
- 模型/Tool 文本进入终端前删除可能改写终端状态的控制字符；
- 只有 Provider 明确返回的 reasoning_content 会显示，不伪造隐藏思维链。

## 6. 协议与生命周期

每一帧都是 UTF-8 单行 JSON，最大 2 MiB：

~~~json
{"v":1,"id":"ui-1","type":"turn.start","payload":{"session_key":"default","text":"你好"}}
{"v":1,"id":"ui-1","type":"response.ok","payload":{}}
{"v":1,"type":"event.turn_started","payload":{"turn_id":42,"session_id":7}}
~~~

~~~mermaid
sequenceDiagram
    participant U as Owner
    participant T as pi-tui
    participant B as Python Bridge
    participant C as Agent Core
    U->>T: Enter 提交
    T->>B: turn.start
    B-->>T: response.ok
    B->>C: TurnService.handle
    C-->>B: model_reasoning / usage / text delta
    B-->>T: event.*
    C-->>B: tool_requested
    B-->>T: event.tool_requested
    alt 需要审批
        C-->>B: approval_required
        B-->>T: event.approval_required
        U->>T: deny / once / session / always
        T->>B: approval.resolve
        B->>C: continue_approval
    end
    C-->>B: turn_finished 或 turn_failed
    B-->>T: 终态事件
~~~

同一时刻只能有一个前台 Turn。失败和取消会恢复已提交草稿；如果用户在运行期间又输入了内容，恢复时会合并，
不会覆盖新草稿。

────────────────────────────────────────────────────────────────────
 上下文 12.4k/128k · 输入 10.8k · 输出 1.6k · 工具 1 · 迭代 2 · 耗时 842 ms
┌ 输入区：Enter 发送；Shift/Alt+Enter 换行 ─────────────────────────┐
└──────────────────────────────────────────────────────────────────┘
~~~

交互规则：

- Reasoning 默认展开，使用中文标签和弱色；内容语言由最新 User 消息对应的 Core Prompt 约束；
- Tool 行永远可见，展开后显示参数、requested→started→finished、耗时和安全结果预览；
- Ctrl+O 展开/收起全部活动，/trace <编号> 控制单项；
- ScrollView 的 follow:end 只在跟随态追踪输出，人工上滚后保持位置；
- pi-tui Alt Screen 负责鼠标拖选和 OSC52，选择不会因为 Assistant 组件重建而丢失；
- /copy 使用 macOS pbcopy 或 OSC52 复制最后一条完整 Assistant 原文；
- /lang zh|en 只切 UI 文案，默认中文；
- Header/Telemetry 在窄终端截断，不允许横向溢出。

## 8. 审批 Overlay

~~~text
┌─ 审批 #9 · run_command ─────────────────────────────────────────┐
│ run lark-cli                                                    │
│ {"program":"/usr/local/bin/lark-cli","args":["doc","list"]}     │
│                                                                 │
│ [1 拒绝]  [2 仅一次]  [3 本次运行]  [4 始终允许]                │
└─────────────────────────────────────────────────────────────────┘
~~~

- Esc 或 1 = Deny；2/3/4 对应 Once/Session/Always；
- Core 没有发布的 grant mode 不显示、按键也无效；
- Overlay 存在期间禁止第二个 Turn；
- Always 只对 Core 认可的精确命令或明确 Skill 生效，文件写入和 inline AppleScript 不能持久放行；
- UI 不做乐观成功，必须等待 Core 的 Tool/Turn 终态。

## 9. Textual fallback 生命周期

当前保留：

- MINICLAW_TUI=textual 显式启动；
- MINICLAW_TUI=auto 在 Node 版本或构建入口缺失时输出诊断并回退；
- Provider 历史、错误摘要、Reasoning 语言、长文本恢复和条件跟随修复继续受 Python 测试保护。

删除条件：pi-tui 在支持终端上稳定一个发布周期；Node 安装和构建流程进入 CI/发布包；真实 PTY smoke、选择、粘贴、
审批和异常退出没有 P0/P1 回归。删除必须是独立 PR，不在本次迁移里顺手完成。

## 10. 桌面版路线

桌面版仍可采用 Electron/React 或 Tauri，但现在不需要为它提前实现第二套协议：protocol v1 和 Python Bridge 已经把 UI
与 Core 分开。未来桌面壳应复用相同请求/事件语义，并新增会话列表、产物预览等有版本的新消息；不能让 Renderer
直接访问 Tool、SQLite 或密钥。

## 11. 验收门禁

- Python：历史边界、Provider 兼容、协议、Bridge、Launcher、Textual fallback；
- TypeScript：协议分片、State reducer、长粘贴、流式稳定、滚动、鼠标选择、审批、双语和安全错误；
- 跨进程：真实 Node client 与真实 Python Bridge 完成 hello/shutdown；
- Agent Eval：全部 active Claw-like offline cases；
- 人工 PTY：macOS Terminal 或 IDE Terminal 启动、提交、拖选、审批和退出。

详细文件和调试方法见 [Python Core + pi-tui Bridge 工程文档](../engineering/phase-2/python-core-pi-tui-bridge.md)。
