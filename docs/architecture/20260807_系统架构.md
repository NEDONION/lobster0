# MiniClaw 系统架构

## 当前状态

仓库已完成 Phase 2：CLI Agent、8 个生产 Tool、参数绑定 Approval、exact-argv 命令、pinned HTTPS/SSRF、
ToolRun/Audit、crash recovery、20 条离线 Agent 场景与 DeepSeek live smoke。飞书、长期 Memory、Skills 和自动
演进尚未实现：

实现边界：

- `paths.py` 只派生绝对状态路径；
- `env.py` 只解析私密 `.env`，不执行 shell；
- `config.py` 解析和校验 TOML/环境覆盖，但不保存 Key；
- `providers/` 负责 HTTP、SSE、协议收窄和有限重试；
- `agent/context.py` 组合身份与历史；
- `agent/runner.py` 执行最多 8 次模型/工具循环；
- `agent/turn.py` 编排一次 Turn 的持久化终态；
- `policy/` 执行 Workspace、exact command、HTTPS/DNS、风险和审批决策；
- `tools/` 提供 Registry、唯一 Executor，以及系统、文件、搜索、写入、命令和 HTTPS 共 8 个 Tool；
- `storage/` 管理 SQLite、会话、ToolRun、Approval、PolicyRule、crash recovery 与脱敏 Audit；
- `evals/` 严格加载 JSONL 场景，用 ScriptedProvider 驱动真实 Agent/Policy/Tool/SQLite 链路并做确定性断言；
- `bootstrap.py` 组合初始化；`doctor.py` 做七项只读诊断，不执行命令、DNS、网络、Approval 或修复；
- `cli.py` 只解析、装配、输出和映射退出码；`eval` 分支不加载用户状态或 `.env`，`chat` 分支仍使用
  真实状态和 Provider。

## 当前已实现的一条消息链路

```mermaid
sequenceDiagram
    autonumber
    actor User as 用户
    participant Channel as CLI
    participant Turn as TurnService
    participant Context as ContextBuilder
    participant Agent as AgentRunner
    participant Model as Model Provider
    participant Exec as "Registry / Executor / Policy"
    participant Tool as "Read-only Tool"
    participant Store as "SQLite / Audit"

    User->>Channel: 发送文本
    Channel->>Turn: owner + session + text
    Turn->>Store: queued Turn + User Message
    Turn->>Store: queued → running
    Turn->>Store: 加载最近会话历史
    Turn->>Context: SOUL + USER + history
    Context-->>Turn: ModelRequest
    Turn->>Agent: bounded run
    Agent->>Model: OpenAI-compatible SSE request
    alt 最终回答
        Model-->>Agent: Answer
    else 工具调用
        Model-->>Agent: Tool Call
        Agent->>Exec: execute(context, ToolCall)
        Exec->>Exec: get → validate → authorize
        alt 未注册或参数无效
            Exec-->>Agent: tool_not_found / invalid_arguments
        else Policy 拒绝
            Exec->>Store: tool.denied（仅 hash + error_code）
            Exec-->>Agent: workspace_escape / sensitive_path
        else Policy 允许
            Exec->>Store: running ToolRun + tool.started
            Exec->>Tool: execute
            Tool-->>Exec: bounded ToolResult
            Exec->>Store: succeeded/failed + terminal Audit
            Exec-->>Agent: Tool Message JSON
        end
        Agent->>Model: 继续推理
        Model-->>Agent: Answer
    end
    Agent-->>Turn: content + usage + request ID
    Turn->>Store: Assistant Message + completed Turn
    Turn-->>Channel: TurnResult
    Channel-->>User: 展示回答
```

Provider 支持 Tool Call 协议和 reasoning 回传；当前 CLI Registry 已注册 `glob`、`grep`、`read_file`、
`system_info`。未知 Tool 仍走 `tool_not_found` 后备。Policy `DENY` 不创建 ToolRun 或 `tool.started`，但必须先原子写入
脱敏 `tool.denied`；合法调用才进入 running → terminal ToolRun。

## 运行期与数据一致性

```mermaid
stateDiagram-v2
    [*] --> queued: "Turn + User Message 同一事务"
    queued --> running: "记录 started_at"
    running --> completed: "Assistant Message + usage + snapshot 同一事务"
    running --> failed: "保存稳定 error_code"
    running --> cancelled: "取消传播并保存终态"
    completed --> [*]
    failed --> [*]
    cancelled --> [*]
```

CLI 是单进程顺序运行。SQLite 每次 Repository 操作使用短连接、外键、WAL 和 busy timeout；复合状态变更在一个
事务中完成。Provider 使用一个 `httpx.AsyncClient` 连接池，并在 CLI 结束时于 `finally` 关闭。

## 核心约束

- 单用户、单进程、一个 SQLite、一个 Workspace。
- Channel 只转换消息，Agent Core 不依赖飞书 SDK。
- 所有工具在执行前统一经过 Policy Engine。
- 文件路径解析后必须仍位于 Workspace，Shell 不接受拼接字符串。
- 自我改进只修改版本化 Prompt 或 Skill，并经过回放评测和人工批准。
- Telegram 与 Discord 复用 Channel 边界，但不进入 v0.1。
- `doctor` 使用 SQLite `mode=ro`，诊断缺失数据库时不得创建空文件。
- `.env` 必须为 `0600` 普通文件，Key 只存在于进程内存和认证 Header。
- CLI one-shot 只在模型、Agent 和 SQLite 全部成功后输出最终回答。
