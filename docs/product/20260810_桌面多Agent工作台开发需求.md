# Lobster0 Desktop 多 Agent 工作台开发需求

> 日期：2026-08-10
> 文档类型：产品开发需求
> 状态：`TARGET CONFIRMED / IMPLEMENTATION PENDING`
> 适用范围：Desktop D1～D5

## 1. 决策摘要

Lobster0 Desktop 改为以 LobsterAI Cowork 为主体的通用工作台：用户打开应用后，首屏中央直接出现可用的
大对话框，不再要求先进入首页、再点击“新建任务”才能输入。

产品吸收两类开源项目的长处：

- LobsterAI（MIT）：Cowork 首屏、对话输入、附件、模型、Workspace、Agent 选择和通用办公任务体验；
- OpenAgents（Apache-2.0）：Agent 列表、任务线程、参与状态和右侧共享产物；
- Lobster0：继续提供唯一的 AgentRuntime、Provider、Policy、Approval、Workspace、ArtifactStore 和 SQLite。

本轮不是另起一套 Agent 平台，也不把 OpenAgents 的网络运行时或 LobsterAI 的后端整体搬进来。Desktop 只是
Lobster0 Core 的图形化工作台。

一句话定义：

> 打开即聊、可带文件、可选工作空间和 Agent、能看执行与产物，并能让受限子 Agent 协作的本地通用工作台。

## 2. 为什么重做当前桌面入口

现有 W0/W1 development build 已具备真实任务执行、审批、取消、历史和设置，但核心输入框只在任务页出现。
首次打开应用时，用户先看到状态首页，需要点击“新建任务”后才能对话。这不符合通用 Agent 工作台的预期，
也直接造成“桌面版连对话口都没有”的体验。

本轮调整的根因目标不是给首页再加一个跳转按钮，而是把“对话工作区”提升为应用默认入口和持续存在的核心。

## 3. 目标用户与核心任务

目标用户是希望让本地 Agent 完成通用办公、研究和开发工作的个人用户。典型任务包括：

- 阅读一组文件并生成报告；
- 调研主题并整理为 Markdown、表格或演示材料；
- 在指定 Workspace 中修改代码或文档；
- 让主 Agent 把可并行的小任务交给受限子 Agent；
- 观察工具执行、处理审批，并在右侧取得任务产物。

首轮不建设企业组织、多人实时协作、Agent 市场或公开 Agent 网络。

## 4. 产品信息架构

### 4.1 默认布局

Desktop 使用浅色三栏工作台，右栏按上下文出现：

```text
┌──────────────┬──────────────────────────────────┬──────────────────────┐
│ 新建任务      │ 当前任务 / 对话与执行时间线        │ 共享产物              │
│ 搜索与历史    │                                  │ 参与 Agent            │
│ Agent 列表    │        打开即用的大对话框          │ 文件预览              │
│ 自动化        │ 附件 · 模型 · Workspace · Agent   │                      │
│ 设置          │                                  │                      │
└──────────────┴──────────────────────────────────┴──────────────────────┘
```

- 左栏承担导航、任务线程和 Agent 入口；
- 中栏始终是当前对话，空任务时展示大输入框，已有消息时输入框固定在底部；
- 右栏展示当前任务的 Artifact、子 Agent 参与状态和安全预览；无内容时可以收起；
- 小窗口隐藏右栏，左栏可折叠，但输入框始终可用。

### 4.2 首屏

首屏必须满足：

1. 应用完成 Core bootstrap 后，中央立即可输入文字；
2. 输入区内或紧邻区域提供附件、模型、Workspace 和 Agent 选择；
3. 用户按 Enter 或点击发送即可创建并开始任务；
4. 最近任务在左栏可见，不用先离开首屏；
5. Core 尚未连接、配置缺失或启动失败时，输入区明确禁用并给出修复入口。

### 4.3 任务进行态

发送后，中栏从空态自然切换为任务线程：

- 展示用户消息、Agent 可见回复、Tool 状态、审批、错误、取消和最终结果；
- 不展示隐藏思维链、原始 Secret、完整 Tool 参数或未脱敏 Tool 输出；
- 运行中发送键变为停止键；
- 可继续追问，使用同一 Lobster0 Session；
- 应用重启后可恢复历史；未完成任务明确显示为 interrupted，不自动重放副作用。

## 5. 核心功能需求

### 5.1 对话输入

- 首屏和任务页共用同一个 Composer，不维护两套输入逻辑；
- 支持多行文本、输入法、粘贴、Enter 发送和 Shift+Enter 换行；
- 失败或取消前尚未提交的文本不丢失；
- 超出 Core 协议限制时在本地提示，不发送截断内容；
- 发送按钮、停止按钮和忙碌状态可被键盘与读屏软件识别。

### 5.2 附件

- 支持通过按钮选择本地文件，后续可以增加拖放；
- 附件先经过 Core admission，再进入现有私有 ArtifactStore；
- Renderer 只持有受限元数据和 `artifact_id`，不读取任意路径或 base64；
- 显示文件名、类型、大小、校验或拒绝状态；
- 附件大小、类型、来源、MIME/magic 和 Workspace/Personal 权限继续由 Core 判定；
- D2 先支持通用文件引用；图片 Vision 仅在 Provider 能力已实现并明确配置时启用。

### 5.3 模型选择

- 下拉框只展示 Core 返回的可用模型，不在 Renderer 保存 API Key；
- 当前只有一个已配置模型时仍显示模型名，但不伪造可选项；
- 切换模型必须绑定当前新任务或后续 Turn，不静默改变正在执行的 Turn；
- 模型不支持附件类型时，发送前给出明确错误。

### 5.4 Workspace 选择

- Composer 中直接显示当前 Workspace；
- 选择新目录继续复用系统目录选择器和受管 Bridge 重启；
- 活跃 Turn 或待审批存在时不允许切换；
- 切换失败恢复旧 Workspace，并保留输入草稿；
- Renderer 不枚举 Workspace 内容。

### 5.5 Agent 选择与列表

Agent 是 Lobster0 内的受控执行配置，不是第二套 Runtime：

- `Main Agent` 始终存在并使用当前 Lobster0 Runtime；
- D2 可提供少量明确用途的内置 Agent 配置，但所有配置仍走同一 Core；
- D4 才展示真实可运行的子 Agent 和参与状态；
- 未实现的 Agent 不显示为可点击入口；
- Agent 不能携带独立 Secret、绕过 Policy 或扩大 Workspace 权限。

### 5.6 任务线程

- 左栏展示最近 Session，点击后加载历史；
- 新建任务生成新的 Session key，并保留当前草稿的明确处理；
- 线程显示标题、更新时间和运行/完成/失败/interrupted 状态；
- 搜索优先复用现有 SQLite/FTS 能力，不在 Renderer 建本地索引；
- 多 Agent 子任务归属于父任务，不伪装成互不相关的顶层对话。

### 5.7 共享产物

- 右栏按当前任务列出 Core 授权的 Artifact；
- 展示名称、媒体类型、大小、来源 Agent、创建时间和状态；
- 文本、Markdown、图片和安全的结构化内容可以内置预览；
- 其他文件提供“用系统打开”或“在 Finder 中显示”，动作由 Main/Core 校验；
- 预览失败不能影响对话和任务终态；
- 不扫描 Workspace 猜测哪些文件是结果。

### 5.8 多 Agent 协作

D4 的 Multi-Agent 是受限、可解释的 depth-1 协作：

- 主 Agent 可以创建有明确目标的子任务；
- 子 Agent 使用隔离 Session，并继承权限、工具和预算的严格子集；
- 子 Agent 不能再创建子 Agent；
- 子 Agent 不能自行审批、外发消息、创建自动化、安装 Skill/MCP 或修改 Policy；
- 父任务显示参与 Agent、状态、耗时、预算和最终回传摘要；
- 子 Agent 的产物通过同一 ArtifactStore 进入右栏，并记录来源；
- 取消父任务会向运行中的子任务传播取消；
- 重启后状态可恢复，完成通知幂等，不重复写入父会话。

## 6. 视觉与交互原则

- 默认浅色，使用低饱和中性色、清晰层级和少量品牌强调色；
- 参考 LobsterAI 的 Cowork 结构，不照搬其深色皮肤；
- 参考 OpenAgents 的 Agent/Thread/Artifact 信息关系，不复制其品牌素材；
- 输入框是视觉主角，空态不堆叠统计卡片；
- Tool、审批和子 Agent 状态使用紧凑卡片，不建设复杂拓扑图；
- 主要交互支持键盘，正文和控件满足基本对比度与焦点可见性。

## 7. 技术与安全约束

- Electron Renderer 保持 `sandbox=true`、`contextIsolation=true`、`nodeIntegration=false`；
- Renderer 只能调用固定 Preload API；
- Electron Main 只负责窗口、文件选择、Bridge 生命周期和受控系统动作；
- Python Bridge 是 Desktop 到 Core 的唯一业务入口；
- Policy、Approval、Workspace、SQLite、ArtifactStore 和 AgentRuntime 只有一套；
- 所有新 Bridge 请求都要版本化、精确字段校验、大小上限和稳定错误码；
- 不把 Secret、绝对敏感路径、原始附件或隐藏 reasoning 写入日志和 UI；
- 不引入 FastAPI、第二套数据库、第二套模型循环或前端直连 Provider。

## 10. 完成标准

Desktop D1～D5 全部完成时，至少满足：

1. 启动应用后无需额外跳转即可发送真实任务；
2. 同一个 Composer 支持文字、附件、模型、Workspace 和 Agent 选择；
3. 对话、Tool、审批、取消、历史和恢复继续走现有 Lobster0 Core；
4. 右栏能列出并安全处理当前任务的真实 Artifact；
5. 至少一个真实 depth-1 子 Agent 可从父任务启动、回传、取消和恢复；
6. Agent 列表、任务线程、参与状态和产物来源与后端状态一致；
7. Renderer 没有 Node、本地数据库、Secret、文件系统或 Provider 直连权限；
8. 自动化测试、构建、文档校验、Electron 手工视觉 smoke 和受控 Provider smoke 有可复现记录；
9. 所有未实现能力继续隐藏或标注 pending，不用静态演示代替功能；
10. 上游代码移植满足 MIT/Apache-2.0 的归属和修改说明要求。

安装包签名、自动更新、多人实时协作、Agent 市场、递归 Agent 网络、内置 Office 编辑器和公开发布运营不属于
D1～D5 完成标准，后续有真实需求时单独立项。
