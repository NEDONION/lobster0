# MiniClaw 本地运行指南

## 当前可以运行什么

当前已接通真实纵向主链路和离线 Agent 回归链路：

```text
CLI chat → ContextBuilder → AgentRunner → DeepSeek V4 Pro / ToolExecutor → SQLite
CLI eval → JSONL cases → ScriptedProvider → 同一 Agent/Tool/SQLite → verifier
```

当前支持幂等初始化、离线诊断、one-shot/TTY 对话、`system_info`、Workspace 内 `read_file/glob/grep`，
以及 10 条 Claw-like query 的离线回归。文件写入、HTTP、Shell、飞书、Telegram 和 Discord 仍是后续阶段。

## 1. 环境要求

- Python 3.12 或更高版本；
- `uv`；
- macOS 或 Linux；
- `init`、`doctor` 和离线测试不需要模型 Key 或外网；
- `eval list/validate/run --suite offline` 不需要 `init`、模型 Key 或外网；
- `chat` 需要有效的 DeepSeek Key 和网络。

## 2. 安装

从仓库根目录执行：

```bash
uv venv
uv sync --extra dev
uv run miniclaw --version
```

运行依赖只有 HTTPX；开发依赖使用 Ruff。项目使用 `src/` layout，CLI 入口由 `pyproject.toml` 的
`miniclaw = "miniclaw.cli:main"` 提供。

## 3. 配置模型凭据

复制模板：

```bash
cp .env.example .env
chmod 600 .env
```

编辑 `.env`：

```dotenv
MINICLAW_MODEL_API_KEY=your-deepseek-api-key
```

规则：

- `.env` 必须是普通文件，POSIX 权限必须为 `0600`；
- 只支持简单 `KEY=value`，不会执行 shell、变量展开或 command substitution；
- `chat` 固定从当前工作目录加载 `.env`；
- 已存在的进程环境变量优先，不会被 `.env` 覆盖；
- `.env` 已被 Git 忽略，禁止复制到文档、issue、日志或测试 fixture；
- `init` 与 `doctor` 不读取 `.env`。

模型默认配置由初始化生成：

```toml
[agent]
model = "deepseek-v4-pro"
max_tool_iterations = 8
context_budget_tokens = 32000
tool_result_max_chars = 20000

[provider]
base_url = "https://api.deepseek.com"
api_key_env = "MINICLAW_MODEL_API_KEY"
timeout_seconds = 120
```

## 4. 初始化

默认状态目录是 `~/.miniclaw`：

```bash
uv run miniclaw init
```

开发或隔离验证建议显式指定绝对目录：

```bash
uv run miniclaw init --home /absolute/path/to/miniclaw-state
```

也可以使用环境变量：

```bash
MINICLAW_HOME=/absolute/path/to/miniclaw-state uv run miniclaw init
```

优先级是 `--home`、`MINICLAW_HOME`、`~/.miniclaw`。相对路径返回退出码 2。

初始化状态：

```text
~/.miniclaw/
├── config.toml
├── miniclaw.db
├── SOUL.md
├── USER.md
├── MEMORY.md
├── memory/
├── prompts/versions/
├── skills/versions/
├── evals/baseline/
├── evals/failures/
├── workspace/
├── logs/
└── run/
```

新目录使用 `0700`，新文件使用 `0600`。重复 `init` 只补齐缺失状态和 migration，不覆盖已有身份、记忆或
配置。预置符号链接会被拒绝。

可以编辑个人身份：

```bash
$EDITOR ~/.miniclaw/SOUL.md
$EDITOR ~/.miniclaw/USER.md
```

`SOUL.md` 描述 Agent 的行为原则；`USER.md` 描述 Owner 偏好。每次 Turn 都按固定顺序放入 System Context。

## 5. 离线诊断

```bash
uv run miniclaw doctor
uv run miniclaw doctor --home /absolute/path/to/miniclaw-state
```

`doctor` 只读检查：状态目录、TOML、Workspace、SQLite integrity/Schema、POSIX 权限。它不会加载 Key、调用
模型、创建数据库或修复文件。

## 6. One-shot 对话

```bash
uv run miniclaw chat --message "你好，请用一句话介绍自己"
```

使用隔离状态和命名会话：

```bash
uv run miniclaw chat \
  --home /absolute/path/to/miniclaw-state \
  --session learning \
  --message "解释 Agent Loop"
```

成功时 stdout 只有最终回答。相同 `--session` 会复用历史；默认 session 是 `default`。

## 7. 交互对话

```bash
uv run miniclaw chat
```

示例：

```text
You> 我正在学习个人 Agent
MiniClaw> ...
You> /quit
```

退出方式：`/exit`、`/quit`、EOF 或 `Ctrl-C`。非 TTY 环境必须传 `--message`，防止脚本挂起。

## 8. 配置覆盖

加载顺序：

1. 代码默认值；
2. 状态目录 `config.toml`；
3. 支持的 `MINICLAW_*` 环境变量；
4. 调用方显式覆盖。

常用环境覆盖：

```text
MINICLAW_MODEL_NAME
MINICLAW_MODEL_BASE_URL
MINICLAW_MODEL_API_KEY_ENV
MINICLAW_MODEL_TIMEOUT_SECONDS
MINICLAW_MAX_TOOL_ITERATIONS
MINICLAW_CONTEXT_BUDGET_TOKENS
MINICLAW_TOOL_RESULT_MAX_CHARS
MINICLAW_WORKSPACE
```

配置拒绝未知字段、错误类型、相对 Workspace、携带凭据/query/fragment 的 Provider URL 和损坏 TOML。

## 9. 退出码

| 码 | 意义 |
| ---: | --- |
| 0 | 成功 |
| 1 | `eval run` 至少一条场景失败 |
| 2 | 参数、路径、配置、`.env` 或缺 Key |
| 3 | Provider 认证失败 |
| 4 | Provider/Agent 运行失败 |
| 5 | SQLite、migration 或本地 I/O 失败 |
| 130 | 用户取消 |

错误写入 stderr；正常 one-shot 回答写入 stdout。

## 10. Agent 回归门禁

列出和校验版本化场景：

```bash
uv run miniclaw eval list --root evals/scenarios
uv run miniclaw eval validate --root evals/scenarios
```

运行完整 offline suite：

```bash
uv run miniclaw eval run --suite offline --root evals/scenarios
```

预期为 10/10 PASS。该命令不加载 `.env` 或 `~/.miniclaw`；每条 case 都创建独立临时 state，模型边界使用
ScriptedProvider，但 TurnService、Policy、ToolExecutor、四个只读 Tool 和 SQLite 都是真实生产实现。

新增事故回归和结果短码见
[Phase 2.1C Agent 回归工程文档](../engineering/phase-2/agent-regression-evals.md)。

## 11. 开发检查

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/ruff check --no-cache .
git diff --check
uv build
```

测试使用临时目录、真实 SQLite、HTTPX fake 和标准库 loopback HTTP/SSE Server，不访问外网或个人状态。
当前验证基线是 177/177 tests、10/10 active offline Agent cases 和 Ruff PASS。

更完整的调试、SQLite 检查、真实模型冒烟和故障分诊见
[Phase 1 测试与调试](../engineering/phase-1/testing-and-debugging.md)。

## 12. 当前边界

- 文件写入、HTTP 和 Shell 工具仍计划在 Phase 2；当前只有四个只读 Tool；
- 长期 Memory 和 Skill Loader 计划在 Phase 3；
- 飞书生产 Channel 计划在 Phase 4；
- Telegram/Discord 计划在 Phase 5；
- 受控自我迭代计划在 Phase 6；
- 当前 eval 是演进闭环的确定性回归地基，还没有自动生成、应用或回滚 Prompt/Skill 提案；
- Docker/VPS 发布门禁计划在 Phase 7。

当前 CLI 是真实可用的学习主链路，但不是后台长期在线的 IM Agent。
