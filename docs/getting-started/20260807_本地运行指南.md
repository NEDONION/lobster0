# MiniClaw 本地运行指南

## 当前可以运行什么

Phase 0 已实现可安装的 `miniclaw` 包、安全状态路径、TOML 配置、完整 SQLite v1 Schema、单 Owner
初始化，以及离线本地诊断。Agent 对话、模型 Provider、工具和飞书 Gateway 仍是后续阶段目标。

## 环境要求

- Python 3.12 或更高版本；
- `uv`；
- macOS 或 Linux；
- `init` 和 `doctor` 不需要模型 Key、IM 凭证或网络。

## 安装

从仓库根目录执行：

```bash
uv venv
uv sync --extra dev
```

运行时只使用 Python 标准库；开发依赖当前只有 Ruff。

## 初始化

默认状态目录为 `~/.miniclaw`：

```bash
uv run miniclaw init
```

开发和测试时可以使用显式绝对目录：

```bash
uv run miniclaw init --home /absolute/path/to/miniclaw-state
```

也可以使用环境变量：

```bash
MINICLAW_HOME=/absolute/path/to/miniclaw-state uv run miniclaw init
```

显式 `--home` 高于 `MINICLAW_HOME`。相对目录会以退出码 2 拒绝。

初始化会创建：

```text
~/.miniclaw/
├── config.toml
├── miniclaw.db
├── SOUL.md
├── USER.md
├── MEMORY.md
├── memory/
├── prompts/versions/
├── skills/versions/
├── evals/baseline/
├── evals/failures/
├── workspace/
├── logs/
└── run/
```

新目录使用 `0700`，新建配置和 Markdown 文件使用 `0600`。重复运行只补齐缺失状态并执行尚未应用的
migration，不覆盖已有配置、身份或记忆文件。预置符号链接会被拒绝。

## 配置

Phase 0 支持 `[agent]`、`[provider]` 和 `[workspace]`。加载顺序为：

1. 代码内安全默认值；
2. `config.toml`；
3. 已支持的 `MINICLAW_*` 环境变量；
4. 调用方显式覆盖。

配置文件只保存密钥环境变量名 `MINICLAW_MODEL_API_KEY`，不加载或打印该变量的值。未知字段、错误类型、
相对 Workspace、携带用户名/密码的 Provider URL 和损坏 TOML 都会失败。

## 离线诊断

```bash
uv run miniclaw doctor
uv run miniclaw doctor --home /absolute/path/to/miniclaw-state
```

`doctor` 只读检查以下五项：

- 状态目录；
- TOML 配置；
- Workspace 存在且可写；
- SQLite 完整性和 Schema 版本；
- 状态根与配置的 POSIX 权限。

成功返回 0；路径或配置/诊断失败返回 2；`init` 遇到文件系统或数据库运行错误返回 5。`doctor` 不创建
缺失目录、不创建数据库，也不调用 Provider 或 IM 平台。

## 开发检查

```bash
uv run python -m unittest discover -s tests -v
uv run ruff check .
uv run miniclaw --version
```

测试使用临时目录和真实 SQLite 文件，但不访问网络和个人状态。
